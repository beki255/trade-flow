📑 Executive Summary

TradeFlow is an enterprise-grade logistics orchestration, real-time corridor telematics, and digital smart escrow platform purpose-built for the critical Ethio-Djibouti Trade Corridor. Spanning 900+ kilometers, this corridor handles more than 95% of Ethiopia's international import and export freight trade volume.

Historically, freight operations along this corridor have been hindered by severe operational inefficiencies: unvetted predatory middlemen charging 15–25% brokerage markups, zero in-transit cargo visibility, lengthy multi-day document customs backlogs at Galafi border posts, payment defaults leading to carrier strikes, and an alarming 42% empty backhaul rate.

TradeFlow modernizes this entire ecosystem by unifying cargo owners (shippers), fleet operators (carriers), commercial drivers, and customs clearance regulatory bodies into a singular, synchronized platform. Featuring milestone-locked escrow contracts, live device-level GPS telematics with Haversine geofence proximity detection, single-window electronic customs clearance with cryptographic QR passes, and comprehensive trilingual support (English, Amharic, and Afaan Oromoo), TradeFlow establishes a trustworthy, transparent, and resilient freight corridor.

1. Project Objectives & Scope

1.1 Problem Statement

The Ethio-Djibouti corridor serves as the primary economic lifeline for Ethiopia's 120+ million population. Despite its strategic weight, the logistics sector suffers from four systemic challenges:

  • Predatory Brokerage & Price Opacity: Informal truck brokers in Addis Ababa and Djibouti manipulate spot pricing, taking exorbitant fees while offering zero legal accountability for cargo safety.
  • Payment Insecurity & Working Capital Strain: Carriers often wait 30–60 days to receive freight settlements after delivery, causing liquidity crises. Conversely, shippers risk driver abandonment once upfront deposits are remitted.
  • Customs Bottlenecks & Demurrage Costs: Manual, paper-based customs declarations create days of queues at the Galafi border gate and Modjo dry port, costing millions in demurrage penalties annually.
  • Lack of Real-Time Telematics & Visibility: Once vehicles depart inland terminals, shippers enter a communication black hole without reliable ETA forecasts or incident detection.

1.2 Project Objectives

  • Automate Freight Discovery: Create a digital spot freight marketplace connecting verified shippers directly with licensed transporters.
  • Eliminate Payment Risk via Smart Escrow: Lock freight funds into an automated escrow vault before vehicle dispatch, guaranteeing payment release upon verified electronic Proof of Delivery (e-POD).
  • Provide Continuous Corridor Telematics: Equip commercial drivers with a mobile telematics application streaming live coordinates, detecting checkpoint arrival via geofencing, and broadcasting real-time route hazards.
  • Accelerate Customs Clearance: Implement single-window digital manifest dossiers and cryptographic QR transit passes to reduce border gate inspection time from hours to seconds.
  • Ensure Nationwide Inclusion: Deliver full trilingual localization in English, Amharic, and Afaan Oromoo with adaptive Dark/Light theme ergonomics.

1.3 Project Scope

The project encompasses a complete monorepo architecture with a Next.js 14 Web Portal, a React Native / Expo Native Mobile Application, an Express.js / TypeScript REST microservice API, a PostgreSQL database managed via Prisma ORM, and WebSocket telematics streaming. All core corridor workflows—load posting, bidding, vehicle dispatch, GPS telemetry, escrow settlement, and customs inspection—are fully implemented, tested, and operational.

4. System Design & Database Architecture

4.1 Relational Data Models (Prisma Schema)

The relational persistence layer is structured into 10 cohesive models enforcing referential integrity:

  • User: Stores authentication credentials, user role, business registration (TIN, trade license), and verification status.
  • Vehicle: Details carrier fleet trucks, capacity (Tons/CBM), fuel type, insurance documents, and telematics identifiers.
  • DriverProfile: Maps individual drivers to user accounts, assigned vehicles, license classes, and safety ratings.
  • Load: Represents cargo consignments posted by shippers, specifying origin/destination coordinates, cargo type, and budget.
  • Bid: Captures transporter bids, proposed pricing in ETB, and transit timeline commitments.
  • Shipment: Encapsulates active corridor transit missions, linking the awarded bid, assigned vehicle, driver, and live GPS coordinates.
  • CustomsClearance: Houses the single-window electronic customs dossier, risk clearance line, certificate number, and digital QR seal.
  • Payment: Manages the digital smart escrow financial ledger, recording payment method (Telebirr/CBE Birr), locked amounts, and settlement timestamps.
  • IncidentReport: Records real-time corridor delays and route hazards with GPS stamps, severity levels, and optional photo evidence.
  • Rating: Bidirectional feedback system enabling shippers and transporters to score each other across verified shipments.

5. Implementation Details & Core Modules

5.1 Geofenced Checkpoint Verification Algorithm

The platform guarantees that drivers cannot falsely report checkpoint arrivals. The driver's device coordinates are evaluated against the official waypoint coordinates using the Haversine trigonometric formula: 

// Haversine Proximity Check (apps/mobile/src/screens/driver/tabs/CheckinTab.tsx)
const R = 6371; // Earth's radius in km
const dLat = (wpLat - liveLat) * (Math.PI / 180);
const dLon = (wpLng - liveLng) * (Math.PI / 180);
const a =
  Math.sin(dLat / 2) * Math.sin(dLat / 2) +
  Math.cos(liveLat * (Math.PI / 180)) * Math.cos(wpLat * (Math.PI / 180)) *
  Math.sin(dLon / 2) * Math.sin(dLon / 2);
const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
const distanceKm = Math.round(R * c);

// Unlocks check-in button only when driver is within 15 km of designated hub
const isWithinGeofence = distanceKm <= 15;

5.2 Milestone-Based Smart Escrow State Machine

To eliminate financial trust deficits, the backend enforces a deterministic state machine on all freight payments:

  • State 1 (PENDING): Consignment bid accepted; shipper instructed to deposit freight funds.
  • State 2 (HELD_IN_ESCROW): Funds locked in platform vault under cryptographic escrow hash. Vehicle dispatch is unlocked.
  • State 3 (CONFIRMED): Cargo reaches destination; recipient verifies condition and signs digital e-POD.
  • State 4 (SETTLED): Platform releases 95% of freight fee directly to carrier's wallet and retains 5% service commission.
